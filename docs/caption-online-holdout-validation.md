## 验证约束

本轮从发布者官方下载此前没有参与本项目调试的视频；不是把本项目生成的字幕烧录回视频作为“参考”。视频、音频、OCR、出版方字幕和原始推理结果仅保存在 Git 忽略的 `.validation/` 内，不把第三方视频重新上传 GitHub。

先通过视频 10%、30%、60%、85% 位置的解码画面确认硬字幕，再冻结已有 r7 候选参数：20 秒音频核心窗口、左右 4 秒上下文、Whisper large-v3 CUDA、无 OCR/预期文本提示、WhisperX v4 质量守卫、SaT 阈值 0.25、软句法依赖保护、通用 NLLB 翻译。录入来源、完整文件 SHA-256、脚本 SHA-256 和冻结时间；本轮没有按测试结果调整解码参数。

## 验证内容与边界

- 全片音频实际执行 GPU ASR → WhisperX → 学习句分段 → 翻译；不截取容易片段。
- 另跑同一模型、关闭 VAD 的全音频连续识别作为对照，不把它当作标准答案。
- 全片解码并约每 0.5 秒提取画面底部英文硬字幕；保留空帧、图形文字、识别错误和未匹配字幕。采样并不是逐帧 OCR，底部区域也不覆盖所有教学幻灯片中央文字。
- OCR 文字匹配率只用于发现遗漏；唯一完整短语的时间锚点用于发现明显错位。原字幕显示时刻不等于单词发声边界，不能把该指标称作语音对齐准确率。
- TED 官方英文字幕文本仅用于独立整篇编辑距离对照，计算替换、漏词和插入；大小写/标点统一，数字写法和缩写不暗中修正。去除明确的笑声/掌声/音乐标签，其他括号文字保留。出版方字幕仍可能编辑口语，故该 WER 不是人工逐词听审的语音准确率。
- 整条流水线检查词序、词数、来源 ID、断句覆盖和翻译输入是否保持；结构测试通过不意味着达到 95% 质量门槛。

运行位置：`.validation/online-holdout-r1/`。`freeze.json` 为推理前冻结记录，`manifest.json` 为来源与文件指纹；各阶段分别保留日志和原始结果。

## 新视频暴露的真实缺陷

1. **缩写句点误判**：`The Interview` 约 91.8 秒、259–263 秒，学习句切在 `Ms.` 与姓氏之间。当前强标点分支把句点作为句末，实体识别未稳定保护称谓；这是通用缩写处理缺陷，不应通过替换某个人名来修补。
2. **无标点对话合句**：同片约 65–83 秒，多个说话人的轮次合成一个学习单元，翻译出现省略/语义串联。仅降低 SaT 阈值与放松宽泛依存保护仍不够。
3. **演讲长句与漏译**：`How to start a movement` 约 23–42 秒仍产生一个 63 词单元，中文没有表达全部英文内容。翻译状态虽然是 `generated_unreviewed`，实际仍有漏译；不能只检查译文非空或长短比例。
4. **疑似识别幻觉/窗口重复**：部分演讲开头出现译者署名样式文本，部分对话出现窗口附近重复词。保留原始解码窗口和对照输出，不能通过全局去重或删除所有短词处理，否则会伤害真实口吃、重复强调、训练计数。
5. **参考提取污染**：TED 画面中的署名、照片来源以及 `(Laughter)` 等标签混入底部 OCR；VOA 教学幻灯片还会把文字放在中央。OCR 匹配失败不能一概归因于 ASR 漏识别。

因此本轮结论是：**新视频整片验证已完成，r7 候选未通过发布验收；不是已经解决断句和翻译问题。** 下轮应针对通用缩写与标点恢复、说话轮次边界、译文语义覆盖和非语音幻觉设计独立对照，不继续只调分句长度。任何依据本轮反例修改后的方案都应把这 6 片标为开发/回归集，再使用未参与修改的备用视频或其他新素材验证，不能重复声称同一测试集仍是未见过的最终验收集。
