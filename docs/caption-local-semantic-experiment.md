# 本地语义断句与上下文翻译对照

日期：2026-10-08。此页记录开发实验，不是正式版本的准确率承诺。

后续：用户批准先在真实学习中试用，已将本地上下文翻译接入服务并完成手机端发起验证；未采用退步的断句候选。见 [试用接入说明](context-translation-trial.md)。本页其余内容保留为接入前的实验记录，不代表最终联合质量已达标。

## 目标与边界

仍按 [90% 整句联合验收](caption-joint-accuracy-plan.md) 执行，不能把模型调用成功率、JSON 完整率、文字保留率或出版字幕句界 F1 当成联合正确率。已有 11 部视频属于开发/回归材料，不能重新命名为未调参盲测集。尚无完整独立的发音起止、语义句界及中文审校参考，因此联合准确率仍未知。

本轮优先复用完整音频已经产生的逐词缓存，避免重新生成 ASR。改变学习句时，只改变原词序列中的分组；原始词、词序和时间戳不取自语言模型。出版字幕与 OCR 只用于评价，不放入模型的修复提示。

## 实际测试的方案

1. **直接输出词序号**：让模型选择句末序号，严格拒绝越界、无序、重复序号和截断回答。实测出现较多越界回答，回退保留证据；未采用。
2. **句子分组提议**：模型提出句子后，与整个输入窗口逐词核对。只容许大小写和标点差异，再映射为原始词索引；改词、漏词、扩写缩写或在词内断开都会拒绝。最终输出使用原文，不采用模型改写文字。
3. **去标点与通用示例对照**：测试去掉 ASR 标点的分析视图，以及不取自测试视频的通用示例。所有窗口覆盖整片转录，重叠上下文不重复计入词范围。
4. **独立证据保留**：保留强声学换人证据和两个文本模型一致支持的原边界；语言模型新增边界还需其他信号支持。失败窗口保持原边界，不悄悄改变原结果。
5. **逐边界判断**：对全片候选边界判断“切开/合并”，用必填编号的 JSON schema 防止少返回条目，而不是让模型重新抄写转录。
6. **上下文翻译**：每个目标句带前后文，但翻译只对应自身编号；检测编号缺失、重复、英文回退和数字变化。失败结果保留，使用必填键的逐条请求重试，不用空输出冒充翻译成功。

## 4B 模型的全片结果：没有优于原方案

模型为电脑上已有的 `qwen3.5:4b-q4_K_M`，摘要 `2a654d98e6fba55d452b7043684e9b57a947e393bbffa62485a7aac05ee4eefd`。实际推理通过本地 Ollama，记录模型显存占用、完整请求及原始回答。

每种断句变体均覆盖六部完整视频的缓存转录，其中三部 TED 有独立出版英文文本。下表是这三部**全文精确标点句界的合并 F1**，不是音频对齐或翻译准确率；它也会把合理的不同断句计作不一致。

| 方案 | 句界 F1 | 正确 / 预测 / 参考边界 |
| --- | ---: | --- |
| 原 SaT + 标点 + 声学保护 | 83.33% | 140 / 167 / 169 |
| 4B 直接输出序号 | 77.02% | 124 / 153 / 169 |
| 4B 完整句子分组 | 78.63% | 138 / 182 / 169 |
| 分组 + 保留独立证据 | 81.63% | 140 / 174 / 169 |
| 去输入标点 | 70.97% | 110 / 141 / 169 |
| 去标点 + 保留独立证据 | 78.40% | 127 / 155 / 169 |
| 通用示例 + 去标点 | 77.95% | 129 / 162 / 169 |
| 通用示例 + 保留独立证据 | 80.36% | 135 / 167 / 169 |
| 必填编号的逐边界判断 | 78.41% | 138 / 183 / 169 |

因此不能因为模型更“智能”就替换默认断句。实测问题包括合并完整短句、把称呼错配到另一句、沿用错误标点、过度拆分以及自动删掉重复词。三千余 token 的单窗口思考模式探针未在输出预算内给出最终答案，也没有计作完整视频实验或成功结果。

## 更换 7B 模型后的全片结果

免注册模型 `qwen2.5:7b-instruct-q4_K_M` 的模型摘要为 `845dbda0ea48ed749caafd9e6037047aa19acfcfd82e704d7ca97d631a0b697e`。下载校验完成后，在同一六部完整缓存转录上执行三种方案，而不是只选择几个失败片段。显存使用约 4.19 GB，部分计算卸载到 CPU，不能称为全 GPU 推理。

| 方案 | 句界 F1 | 正确 / 预测 / 参考边界 |
| --- | ---: | --- |
| 7B 去标点后句子分组 | 72.96% | 112 / 138 / 169 |
| 7B 分组 + 保留独立证据 | 79.01% | 128 / 155 / 169 |
| 7B 必填编号的逐边界判断 | 76.83% | 131 / 172 / 169 |

三种方案均未超过基线，未提升为默认实现。所有变体是反复使用同一开发集，不能把运行次数累加为新验证视频数量。出版文本有删改口语和缩写标点，部分“未匹配”不是实际错误；这些分歧保留待审，不能为了提高分数直接删除。也不能用这个指标推导最终整句正确率。

## 验证工具的修正

`audit_pipeline_integrity.py` 在显式指定新学习句目录时，不再默认混入另一轮旧翻译。若指定旧翻译，字段不一致会明确失败。除词范围守恒外，新增逐句文字与原词范围一致、起止时间与原词时间一致的严格检查，防止只保留索引却改了文字或时间。无报告或完整性失败时返回退出码 2，避免批处理把失败报告误当成通过。

11 部最终上下文翻译全部通过严格完整性检查；最后一组 7B 断句候选的六部全片也通过词序、词范围及时间检查，但句界质量退步。284 项电脑端单元测试通过；完整性通过、单元测试通过均不代表识别或译文准确。

## 本地运行与隐私

- 仅允许数字回环地址 `127.0.0.1`，禁用请求代理；模型服务设置 `OLLAMA_NO_CLOUD=1`，没有上传视频、音频或字幕到云端。
- 4B 使用已有本地模型。另从官方 Ollama 模型库免注册下载 `qwen2.5:7b-instruct-q4_K_M`（约 4.7 GB），放入 C 盘独立实验目录，不覆盖原模型或正式服务。
- 较大模型串行运行，模型空闲 60 秒卸载；实验结束关闭本次创建的服务。
- 模型、视频、逐字文本和原始推理记录在忽略目录或独立模型目录中，不随项目发布。
- 方案参考 [Ollama 结构化输出](https://docs.ollama.com/capabilities/structured-outputs)、[本地部署与云功能关闭](https://docs.ollama.com/faq)；7B 的大小、许可和模型详情见 [官方模型页面](https://ollama.com/library/qwen2.5:7b-instruct-q4_K_M)。模型声称的通用能力不替代本项目测试。

## 复现入口

```powershell
python tools/validation/run_local_sentence_partition.py MANIFEST ALIGNMENT BASELINE OUTPUT --strip-punctuation --few-shot
python tools/validation/run_boundary_decision_experiment.py MANIFEST ALIGNMENT BASELINE OUTPUT

python tools/validation/finalize_context_translation.py MANIFEST PRIOR_TRANSLATION OUTPUT
python tools/validation/audit_pipeline_integrity.py MANIFEST PIPELINE OUTPUT --learning-root LEARNING --translation-root TRANSLATION
python tools/validation/audit_publisher_boundaries.py REFERENCES ALIGNMENT LEARNING OUTPUT
python tools/validation/summarize_local_semantic_experiment.py .validation NEW_SUMMARY.json
python -m unittest discover -s tools/tests/unit -p 'test_*.py'
```

输出目录必须不存在，防止覆盖旧证据。所有生成译文仍标为未审校；结构检查不直接赋予“正确”标签。正式默认流程、手机版本号和 APK 尚未替换。
