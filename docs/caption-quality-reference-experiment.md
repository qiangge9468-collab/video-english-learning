日期：2026-10-07。基线提交：`f5aac21`。手机端仍为 v2.2.0，电脑端仍为 v2.1.0。

## 通用性优化续测（2026-10-07）

不按视频名、指定台词或问题时间点添加识别/翻译答案。新学习句实验默认使用 `TRANSLATION_STYLE=generic`：只规范空白和中文标点，不套用旧版的旅行、装备、人名纠正和固定译文；识别提示仅保留显式配置及标题关键词。旧版正常模式保持兼容，实验开关仍默认关闭。学习句增加 `text_review_required`，即使补识别词通过声学对齐，也不自动成为已校验文字。

新 `recovery_decode.py` 仅在首次缺口识别没有可用的窗口内词时，最多尝试两个不同上下文窗口；只有两个重试的完整有序词序列和时间位置均一致，才接受其中一个并标记待审。不同窗口的同一个模型不是独立真值，此规则是防误插入措施，不是准确率证明。保留重复训练计数和原始词来源，不以全局去重消除 `one, one`。

对 Switzerland 约 04:22 的实际服务输出追踪发现：首次仅解码出窗口前的 `it for me.`，并非目标句先被识别后遭低置信度过滤。无扩窗重试产生目标短语，扩大上下文的另一重试却产生相邻旁白；因此新策略保留分歧，不将较长输出强塞回字幕。这个案例说明需要继续比较识别窗口/模型，不能只降低过滤阈值。

在四部完整音频上重新执行所有语音候选的实际服务补识别（`.validation/generalized-recovery-r3/`）：输入/输出词分别为 1,577→1,759、3,729→4,085、3,826→4,452、2,894→2,974。结果与上一轮实际策略的接受词数相同，**没有证据表明本次上下文一致性规则提高了召回**；价值在于有界重试、记录分歧并避免未经确认的额外插入。

翻译输入在送入模型前检查 token 预算，超限返回显式英文回退，不再静默截取前 512 token；同批其他输入仍可正常翻译。英文完整句对应中文若停在逗号、分号或冒号，触发重试/告警。此类检查不能发现所有漏译、词义错误或幻觉，非空中文依然只是 `generated_unreviewed`。

新增 `run_caption_pipeline_experiment.py` 固定输入音频、补识别词、段及源码 SHA-256，将同一批完整输出串行送入 WhisperX CUDA、SaT/spaCy 和通用模式 NLLB CUDA，避免把不同轮次的成功结果拼接为端到端验收。本轮记录保存在 `.validation/generalized-pipeline-r1/`；最终是否完整执行以 `pipeline.json` 的 `complete` 和各阶段报告为准，`accuracy` 始终为未知、`release_allowed` 为 false，不能将运行完成当成达标。

### 全片检查新发现：不是所有大幅错位都会得到低对齐分数

Bangladesh 的 `But what became clear very quickly ...` 在新管线仍被放到 1,241.14 秒附近，逐词状态显示 `aligned`。查看 1,242 秒和 1,281 秒的真实视频帧，前者硬字幕实际为躲避树枝的现场讲话，后者才出现该旁白；无 VAD 全片识别也将这段旁白放在 1,279.32 秒附近。这支持旧段定位提前约 38 秒的判断，而不是缓存音轨整体偏移。画面字幕时间不是精确听音真值，仍需复核语音边界。

目前有界 ±0.6 秒重对齐不能解决这种量级的大幅漂移。错误旧段占据了语音窗口，单纯“查找空白再补字”也会漏查或把不同内容合成一条学习句。因此下一优先级必须提升为：全片粗定位/跨解码时间轴分歧检查 → 对冲突区间重新识别、重新定位 → 逐词对齐 → 语义断句 → 翻译。不得用更宽的强制对齐窗口盲目抬高分数，也不得按这部视频的 38 秒偏移硬编码校正其他视频。

已新增只读 `audit_transcript_drift.py` 并在四部完整输出上运行，与既有无 VAD 全片对照逐词比较。仅使用双方均唯一出现的五词短语；五个词同方向偏差均超过 3 秒才标记，不用单个异常词平移整句，也不删除重复计数。四部依次检出 4 / 15 / 7 / 3 个短语分歧锚点，涉及 16 / 39 / 19 / 15 个不重复的原词索引。锚点可相互重叠，不等于独立错误段数量；两个解码都可能错，且本对照仍使用同一 ASR 模型，不能认定另一侧是真值。结果在 `.validation/generalized-transcript-drift-r1.json`，仅用于筛查，不自动修改字幕或宣称准确率。

真实译文抽查还显示，新完整句输入下，Switzerland 的隧道长句仍无法可靠译完，现返回明确英文回退，避免把半句中文当成成功；机械 `part` 的词义误译仍然存在。格式/长度门控不能替代翻译模型能力，后续模型比较仍属必要工作。

### 完整译文审计

对四部学习句完整运行本地 NLLB CUDA，分别产生 188 / 212 / 506 / 308 条结果。重新检查输出发现：7 条实际为英文回退，18 条有启发式不完整/结尾标点告警，43 条为数字等确定性转换，其余 1,146 条仅能标记 `generated_unreviewed`，不能当成正确译文。

已确认的例子：Switzerland 关于工程师修十英里隧道的完整英文句，译文停在“建造了一条长 10 英里的道，”而遗漏“让富人通行”的后半句；另有机械零件 `part` 被译成“角色”。这表明整句翻译能避免机械截断输入，却不能保证当前 600M 翻译模型正确理解长句、词义和上下文。新 `translation_status` 区分生成待审、告警、英文回退、确定性转换及失败，不会把非空输出计为准确。

本地记录：`.validation/cohort-report-r1/summary.json`、`.validation/full-translation-audit-r1.json`、`.validation/post-alignment-recovery-r1/` 和 `post-alignment-recovery-r2/`。这些含素材文本的原始输出不上传公开仓库。

## 改动与范围

- 修正长文本分块后名词短语、实体边界保护遗漏 `chunk_start` 的缺陷。
- 单个时间异常或超长文本的词不再使整部视频的动态规划无解；保留该词并在 `oversize_tokens` 中报告，不能把它当作已修复时间戳。
- 将 WhisperX 对齐分数与识别概率区分，旧缓存的对齐分数不再用于低置信度虚词删除。
- 增加默认关闭的 `learning_sentence_mode` 实验：完整学习句用于翻译/练习，短显示块通过 `learning_sentence_id`、词范围和原时间戳关联。实验模式不删除孤立虚词。
- 实验发现依存句法有时跨越句号，进一步修正完整句末 `that.` 被错误并入下一句的情况。
- 修正历史审计脚本的固定零计数；增加只读时间戳审计，检查缺失时间、倒序、重叠、异常长词、低对齐分数。结构检查通过不代表已听音验证。
- 增加独立 OCR 提取、候选比对和严格发布门槛工具。OCR 结果未经校对不能作为准确率证据。

续测已增加对齐异常的有界局部重试、来源保留和实验服务学习句/整句翻译入口。尚未完成的是四个完整视频的独立逐句文字/听音参考校对、完整中文译文准确性审核，以及达到发布标准后启用默认策略。不得因为单元测试通过就启用实验模式或重建用户的正式缓存。

## 95% 发布门槛

每个视频分别检查，不对好坏视频或不同指标取平均来掩盖问题：

1. 校对后的文字准确率（1 − WER）至少 95%。漏词必须计入；金额、数字、英美拼写的归一化规则须预先固定并保留原文。
2. 至少 95% 的已校对语音单元，起止时间均与听音参考相差不超过 0.5 秒。画面字幕起止时间只用于初筛，不直接当语音真值。
3. 至少 95% 的语义单元断句可接受。原视频显示块不等于语言学上的句子，需独立标注。
4. 至少 95% 的中文译文正确保留核心意思、否定、数量和指代。
5. 至少四个不同的完整视频分别达标，至少一个未参与调参。OCR、ASR 自我对照、缺失画面或未校对数据都返回 `insufficient_reference`，不允许发布。

自动 OCR 候选比对的 `ocr_word_recall` 不是上述准确率：它受 OCR 错字、品牌/路牌、画面说明、原字幕改写影响，仅用于定位人工复查点。

本轮已扫描本地五个视频文件的全部可解码画面，按约 0.5 秒取样：Hiking 1,864 帧、Pakistan 786 帧、AIRFLARE 2,628 帧、Switzerland 1,787 帧、Natural English 2,458 帧。后者遇到尾部损坏后记录错误并断点续查，不把解码失败当成无字幕。该扫描不是逐帧人工审核，也不是五个完整音频的识别验证；缺失的视频流无法由 OCR 恢复。

自动匹配仅用于排查：Hiking 可用画面候选词匹配率约 80.8%，Pakistan 约 81.6%，Switzerland 约 56.8%，均未经完整 OCR 校对，**不能当作模型准确率**；AIRFLARE 在检查字幕带内无有效英文字幕参考，数值为未知而非 0% 或 100%。原始候选、未匹配项和全部采样记录留在本地，暂未作为发布证据。

## 可复现工具

所有输出放到被 Git 忽略的 `.validation/`。原视频、原字幕全文、音频、下载模型与私人路径不上传 GitHub。

- `tools/validation/extract_burned_subtitles.py`：`--audit` 扫描视频包；`--preview` 生成检查图；默认按 0.5 秒间隔提取所有可用帧的字幕候选。需隔离安装 `rapidocr-onnxruntime`、OpenCV、PyAV、Pillow。
- `tools/validation/compare_ocr_proposals.py`：按预先人工选定画面字幕区域比对候选，保留未匹配项，不输出发布通过。
- `tools/validation/run_cached_sentence_experiment.py`：使用现有模型与完整词缓存，在新目录生成学习句，不触碰服务数据。
- `tools/validation/summarize_sentence_experiment.py`：复用保存的模型特征重跑策略，并审计原词时间戳。
- `tools/validation/evaluate_caption_reference.py`：审阅后的独立文字/语音参考门槛。缺失或未经校对的参考不能通过。

新回归测试：`test_caption_quality_v210.py` 和 `test_caption_reference_gate.py`。它们检查程序行为、守恒和发布门槛，不能替代真实音频准确性测试。另提供 `render_reference_review.py`，可将指定时刻的真实帧、OCR 候选与缓存匹配文字放在同一检查图中，生成图片不会自动将参考标记为已审核。

新增 `test_caption_guarded_alignment.py`、`test_caption_experiment_integration.py`、`test_caption_recovery_context.py` 和 `test_caption_transcript_drift.py` 覆盖保词、回退状态、数字重复、跨段词顺序、实验缓存隔离、整句翻译输入、上下文分歧、超长输入及翻译状态。最新电脑端单元测试 **156 项全部通过**，其中一项以固定随机种子检查 80 组跨题材、长度、停顿和重复词组合的学习句/显示块范围守恒，不改变输入。上一轮为 133 项中的 130 项通过、3 项失败；失败的历史 `test_model_runtime.py` 依赖工作区已有下载模型。现将该测试前提显式隔离，并新增本地模型缺失的分支测试，没有修改 v2.0.2 服务或为通过测试下载模型。真实模型实验仍使用原项目模型的显式只读路径。测试通过不代表字幕准确率达标。

完整实验工具另包括 `run_full_audio_alignment_experiment.py`、`run_full_audio_asr_comparison.py`、`run_cohort_learning_experiment.py`、`audit_full_audio_speech_coverage.py`、`recover_post_alignment_gaps.py`、`run_service_recovery_experiment.py`、`audit_translation_outputs.py` 及 `summarize_full_cohort.py`。各模型轮次写入不同目录，避免覆盖先前失败结果；重排序回放与模型重新推理分别记录。

## 成熟方案与本项目的取舍

- [WhisperX](https://github.com/m-bain/whisperX)：保留“先识别、再声学对齐”的分层；其对齐器不能修复已经缺失/识别错误的文字，也不能用 CTC 分数冒充 ASR 概率。
- [stable-ts](https://github.com/jianfch/stable-ts)：借鉴识别、对齐/细化、重新分组相分离的思路。官方区分全片文本 `align()` 与限制在已有段范围内的 `align_words()`，后者依赖准确的初始段范围，这与本项目发现的大幅旧段漂移直接相关。该仓库已于 2026-05-30 归档、开发暂停，不能把它当作正在维护的新主依赖；本轮未集成或宣称达到其示例效果。
- [wtpsplit](https://github.com/segment-any-text/wtpsplit)：继续使用本地 SaT 语义边界模型，显示长度约束不强迫整句翻译在固定词数处切开。
- [RapidOCR](https://github.com/RapidAI/RapidOCR)：用独立英文 OCR 提取画面参考，不喂入生成字幕去“纠正”OCR，以免自我验证。OCR 错字、画面说明、翻译式硬字幕和作者改写均需复查。
